# PR 生成规则设计

## 目标

在“创建 Pull Request”弹窗底部增加“生成规则”入口，让用户管理 Markdown 格式的 AI 生成规则。用户可以新增、编辑、导入、单选和设置默认规则。创建 PR 时自动选择默认规则，并在 AI 生成标题与描述时使用所选规则。

当前阶段用于验证产品与技术可行性，规则仅保存在浏览器 `localStorage`。Supabase 持久化、跨设备同步和团队共享留到下一阶段设计。

## 用户体验

### 创建 PR 弹窗

“生成规则”按钮放在创建 PR 弹窗底部操作区，位于“AI 设置”和“AI 生成”之前。按钮显示当前选择，例如“生成规则 · 标准 PR”。

打开创建 PR 弹窗时：

1. 如果存在默认规则，自动选中默认规则。
2. 如果只有一条规则，该规则自动成为默认规则并被选中。
3. 如果没有规则，不选择规则，AI 生成继续使用现有内置提示词。

用户无需打开规则弹窗即可使用默认规则。用户为当前 PR 选择非默认规则时，只改变当前创建 PR 弹窗的选择，不改变全局默认规则。

### 规则管理弹窗

点击“生成规则”后打开独立弹窗：

- 左侧显示规则单选列表。
- 默认规则显示“默认”标记。
- 右侧显示规则名称和 Markdown 内容编辑器。
- 用户可以新增规则、编辑当前规则、导入 `.md` 文件、设为默认。
- 点击“使用此规则”保存当前 PR 的选择并返回创建 PR 弹窗。

当列表只有一条规则时，该规则自动成为默认规则。新增后续规则不会替换已有默认规则。只有用户明确点击“设为默认”才会更改默认规则。

### Markdown 导入

导入只接受扩展名为 `.md` 的文件，不区分扩展名大小写。文件名去掉扩展名后作为规则名称，文件内容载入编辑器，用户可以在保存前继续修改。

以下情况显示错误且不保存：

- 文件扩展名不是 `.md`。
- 文件内容为空。
- 规则名称为空。

## 数据模型

每条规则保存以下字段：

```ts
type GenerationRule = {
  id: string;
  name: string;
  content: string;
  isDefault: boolean;
  createdAt: string;
  updatedAt: string;
};
```

规则数组保存在独立的 `localStorage` 键中。读取失败、JSON 损坏或结构无效时回退为空规则列表，不阻塞创建 PR。

业务约束：

- 全局最多存在一条默认规则。
- 第一条有效规则自动成为默认规则。
- 设置新的默认规则时清除原默认规则。
- 当前 PR 的选择只在创建 PR 弹窗生命周期内保存。

## 模块边界

新增独立的规则领域模块，负责：

- 规则数据校验与规范化。
- 新增和编辑规则。
- 唯一默认规则管理。
- 创建 PR 时的自动选择。
- Markdown 文件名和文件类型校验。
- 将所选规则内容加入 AI 提示词。

`src/main.ts` 负责弹窗渲染、DOM 事件、文件读取和 `localStorage` 的输入输出，不复制领域模块的规则判断。

现有 AI 模块继续负责请求模型。生成提示词由现有分支和提交信息加上当前选择的 Markdown 规则组成；没有选择规则时保持当前提示词行为。

## 数据流

1. 应用启动时从 `localStorage` 读取并校验规则列表。
2. 用户打开创建 PR 弹窗，系统计算本次默认选择。
3. 用户可直接点击“AI 生成”，或打开规则弹窗选择其他规则。
4. AI 生成读取本次选择的规则内容，追加到提示词中。
5. 用户新增、编辑或设置默认规则时，更新规则列表并写回 `localStorage`。
6. 用户关闭创建 PR 弹窗后，本次临时选择被丢弃；下次仍从全局默认规则开始。

## 错误处理

- 非 Markdown 文件、空文件和空名称使用弹窗内错误提示，不关闭弹窗。
- `localStorage` 写入失败时提示用户，保留当前编辑内容以便重试。
- 损坏的本地规则数据不会传入 AI 提示词。
- AI 生成失败保持当前规则选择与表单内容，允许用户重试。

## 测试策略

领域单元测试覆盖：

- 第一条规则自动成为默认规则。
- 多条规则中最多只有一个默认规则。
- 设置新默认规则会清除旧默认规则。
- 新建 PR 自动选择默认规则。
- 当前 PR 选择非默认规则不会修改全局默认。
- `.md` 文件名校验与规则名称提取。
- 空名称和空内容被拒绝。
- 新增和编辑规则保留正确的时间字段。
- 选中规则的 Markdown 内容进入 AI 提示词。
- 没有规则时保持现有 AI 提示词。

完成后运行完整 Vitest 测试和临时目录生产构建，不写入或提交 `dist/`。
