# PR 流式生成与草稿持久化设计

## 目标

改进“创建 Pull Request”弹窗中的 AI 生成体验：标题和描述通过真实 SSE 流逐步显示，不再等待完整响应后一次性填充；用户手写或 AI 生成的内容保存为本地草稿，即使取消或误关弹窗也能在下次打开时恢复。

AI 生成是明确的覆盖操作。已有标题或描述时，开始生成前必须获得用户确认。

## 范围

本阶段包括：

- OpenAI Chat Completions 兼容 SSE 流式响应。
- PR 标题和描述的渐进显示。
- 覆盖前确认。
- 基于 `localStorage` 的 PR 草稿保存与恢复。
- 24 小时过期、最多 50 条草稿和创建成功后的清理。
- 网络中断、主动取消、无效流和存储失败的容错。

本阶段不包括：

- Supabase 或其他服务端草稿同步。
- 多设备或多人共享草稿。
- 非 OpenAI Chat Completions 格式的流式协议。
- AI 生成历史版本或撤销栈。

## 用户体验

### 打开创建 PR 弹窗

草稿按“仓库 + Source + Target”隔离。打开弹窗时：

1. 清理全部超过 24 小时未更新的草稿，并将总数裁剪到最多 50 条。
2. 如果当前仓库和分支方向存在未过期草稿，恢复其标题和描述。
3. 如果没有草稿，标题使用当前默认分支标题，描述为空。

仅打开和查看草稿不会更新 `updatedAt`，不会延长有效期。

### 手动编辑与关闭

- 标题或描述变化后约 300ms 防抖保存。
- 点击取消、按 Escape 或关闭创建 PR 弹窗不会删除草稿。
- 再次打开相同仓库和分支方向的创建 PR 弹窗时恢复草稿。
- 不同仓库或不同 Source/Target 组合互不影响。

### AI 覆盖确认

点击“AI 生成”后先校验 AI 配置。配置缺失时保持现有行为，打开 AI 设置，且不修改标题、描述或草稿。

配置有效且标题或描述非空时，显示确认提示：

> AI 生成会覆盖当前标题和描述，是否继续？

- 用户取消：标题、描述和已保存草稿完全不变。
- 用户确认：立即清空标题和描述，保存新的空白草稿，然后发起流式请求。
- 标题和描述均为空时可以直接开始生成，无需重复确认。

### 流式显示

- 请求使用 `stream: true`。
- 按 OpenAI Chat Completions SSE 格式读取 `choices[0].delta.content`。
- 保持现有 JSON 输出协议：`{"title":"...","body":"..."}`。
- 标题字符到达时实时更新标题输入框；描述字符到达时实时更新描述文本框。
- UI 更新后约 100ms 节流保存草稿，避免每个字符都写入 `localStorage`。
- 生成期间标题、描述和“AI 生成”按钮禁用；按钮显示“生成中…”，避免手动输入或并发生成与流式输出竞争。
- 流结束后重新启用控件。

### 关闭、失败与重试

- 创建 PR 弹窗关闭时通过 `AbortController` 中断正在进行的请求。
- 主动关闭导致的中断不显示错误提示。
- 网络中断、无效 SSE 或最终 JSON 无效时显示错误，但保留已收到的标题和描述。
- 重试 AI 生成仍属于覆盖操作；若当前已有部分内容，再次生成前重新确认。
- 不恢复确认覆盖前的旧内容。

### 创建成功

GitHub PR 创建成功后，立即删除对应草稿。创建失败时保留草稿，允许用户修改并重试。

## 草稿数据模型

```ts
type PullRequestDraft = {
  key: string;
  repository: string;
  source: string;
  target: string;
  title: string;
  body: string;
  updatedAt: string;
};
```

草稿集合保存在独立的 `localStorage` 键 `pr-helper-pr-drafts` 中。

草稿键必须由仓库、Source 和 Target 生成，不依赖流程名称或数组下标。键生成函数必须避免简单字符串拼接造成的歧义，可使用各字段编码后的稳定结构。

## 草稿生命周期

- TTL：自最后一次标题、描述或 AI 流式内容更新起 24 小时。
- 清理时机：应用启动和打开创建 PR 弹窗时。
- 容量：最多 50 条。
- 超出容量：按 `updatedAt` 从旧到新删除，保留最近更新的 50 条。
- 用户编辑：刷新当前草稿的 `updatedAt`。
- AI 清空和流式更新：刷新当前草稿的 `updatedAt`。
- 仅打开查看：不刷新 `updatedAt`。
- 创建 PR 成功：立即删除。
- 取消、关闭、刷新页面或浏览器重启：不删除未过期草稿。

读取 JSON 失败、数组结构无效或字段类型无效时回退为空草稿列表，不阻塞创建 PR。单条损坏数据不应进入 UI。

`localStorage` 读取受限时回退为空列表。写入失败时保留当前内存和表单内容，显示“草稿保存失败”，但不阻止用户继续编辑或创建 PR。

## 模块设计

### `src/lib/pr-drafts.ts`

框架无关的草稿领域模块，负责：

- 草稿键生成。
- 持久化数据解析和校验。
- 24 小时过期判断。
- 最多 50 条裁剪。
- 不可变的新增/更新和删除。
- 安全读取回退。

该模块不访问 DOM，不直接依赖 `window` 或 `localStorage`。时间通过参数注入，便于测试 24 小时边界。

### `src/lib/ai-stream.ts`

流式 AI 模块，负责：

- 发起带 `stream: true` 的 Chat Completions 请求。
- 校验 HTTP 状态和 `text/event-stream` 响应类型。
- 使用 `ReadableStream` 和 `TextDecoder` 处理任意网络分块。
- 解析 SSE 帧、多个 `data:` 行和 `[DONE]`。
- 提取 `choices[0].delta.content`。
- 累积模型文本并增量解析未完成的 PR JSON。
- 处理 JSON 字符串中的引号、反斜杠、换行和 Unicode 转义。
- 每次得到新的标题或描述时回调 UI。
- 流结束后对完整 JSON 做最终校验，要求标题非空。
- 接受 `AbortSignal`，区分主动取消和真实失败。

不支持 SSE 的服务返回明确错误“当前模型服务不支持流式生成”。不静默回退为一次性响应。

### `src/main.ts`

浏览器集成层负责：

- 启动时清理过期草稿。
- 打开创建 PR 弹窗时恢复当前草稿。
- 监听标题和描述输入并防抖保存。
- 在覆盖确认和清空内容之前校验 AI 配置。
- 显示 AI 覆盖确认。
- 清空旧内容并启动流式请求。
- 将流式结果写入表单并节流保存。
- 生成期间控制禁用状态和按钮文案。
- 弹窗关闭时中断请求并立即冲刷尚未落盘的草稿。
- PR 创建成功后删除草稿。

## SSE 与增量 JSON 行为

流解析必须允许：

- SSE 分隔符跨网络块。
- 一个网络块包含多个事件。
- `data:` 后有或没有单个空格。
- 注释、空行和不携带内容的 delta。
- UTF-8 中文字符跨二进制块。
- `[DONE]` 单独或与其他帧同块到达。

增量 JSON 解析器不要求缓冲区当前可被 `JSON.parse` 完整解析。它扫描 `title` 和 `body` 字符串字段并解码已经完整到达的转义序列，返回当前可安全显示的部分。未完成的反斜杠或 Unicode 转义必须等待后续数据，不能显示损坏字符。

收到流结束标记后，对完整模型文本移除可选的 Markdown JSON 代码围栏，再执行最终 `JSON.parse`。最终标题缺失或 JSON 无效时抛出错误，但不清空此前已经显示和保存的部分内容。

## 并发与状态约束

- 每个创建 PR 弹窗最多一个生成请求。
- 生成期间禁止第二次点击生成。
- 生成期间禁用标题和描述输入，避免用户编辑被后续流覆盖。
- 关闭弹窗后，任何迟到的流回调不得继续更新已移除的 DOM。
- 新弹窗拥有新的 `AbortController` 和保存定时器，不复用旧弹窗状态。
- 防抖或节流定时器在弹窗关闭前必须执行最后一次保存或被安全取消。

## 错误处理

- 覆盖确认取消：无副作用。
- AI 配置缺失：保持现有行为，打开 AI 设置，不清空现有内容。
- HTTP 非成功：显示 `AI 请求失败 (<status>)`，保留当前草稿。
- 非 SSE 响应：显示“当前模型服务不支持流式生成”，保留确认后的当前草稿。
- SSE 数据行 JSON 无效：结束生成并提示响应格式错误，保留部分结果。
- 最终模型 JSON 无效或缺少标题：提示错误，保留部分结果。
- 主动关闭弹窗导致 `AbortError`：静默结束。
- 草稿读取失败：回退为空集合。
- 草稿写入失败：提示但不阻断表单操作。
- GitHub PR 创建失败：保留草稿和输入。

## 测试策略

### 草稿单元测试

- 不同仓库、Source 和 Target 生成不同键。
- 同一组合生成稳定键。
- 解析合法数据并拒绝损坏数据。
- 24 小时内保留，达到或超过 24 小时过期。
- 仅打开不会更新 `updatedAt`。
- 更新标题或描述会刷新 `updatedAt`。
- 超过 50 条时保留最近更新的 50 条。
- 删除仅影响指定草稿。
- 存储读取抛错时回退为空列表。

### 流式单元测试

- SSE 帧被拆在任意字符和分隔符位置。
- 一个块包含多个 SSE 事件。
- UTF-8 中文跨二进制块。
- 多个 `data:` 行和 `[DONE]`。
- 标题和描述字段跨块增长。
- 引号、反斜杠、换行和 Unicode 转义。
- 未完成转义不会显示损坏字符。
- HTTP 错误、非 SSE、无响应体、无效事件和主动中断。
- 最终 JSON 校验及代码围栏处理。

### 浏览器验证

- 手动输入标题和描述，取消后重新打开恢复。
- 刷新页面和浏览器重启后，24 小时内草稿仍恢复。
- 覆盖确认取消时内容不变。
- 覆盖确认后旧内容立即清空。
- 使用延迟 SSE 模拟标题和描述逐步显示。
- 流式生成中关闭弹窗，再次打开恢复部分结果。
- AI 失败保留部分结果。
- 创建 PR 成功删除草稿，失败保留草稿。
- 不同流程阶段的草稿不串联。
- 过期和超过 50 条的草稿被清理。

## 验收标准

- 用户在首个 AI 字符到达后即可看到标题或描述变化。
- 已有内容必须确认后才会被 AI 覆盖。
- 取消、误关或刷新后，24 小时内可恢复最近保存的草稿。
- 流式失败或中断不会丢失已经显示的部分内容。
- PR 创建成功后不会再次恢复旧草稿。
- 无规则时和有生成规则时都能流式工作。
- 所有单元测试、临时目录生产构建和模拟 SSE 浏览器流程通过。
